# MIEL+ website

Lebanon-only honey sports-nutrition sachets. Next.js (App Router) + Tailwind 4, hosted on Railway (Europe, ONE replica; see docs/OPERATIONS.md).
Tone: raw, performance-driven, short punchy copy. English only. No medical claims.

## Hard rules
- **New products are added only through `config/products.ts`.** The home lineup, `/products/[slug]` pages, compare strip, sitemap, metadata, JSON-LD and cart all read from it. Never hardcode a product elsewhere.
- **Never invent values.** Unknown nutrition, ingredients, allergens, shelf life and warnings are `null` in config and render as a clean `TBC`.
- Pouch price is one value: `POUCH_PRICE` in `config/site.ts`. Per-sachet price = `perSachet(price)` in `lib/format.ts` (price / 12, rounded to 2 decimals).
- **Product photos:** originals go untouched in `assets-src/<slug>/<name>.webp` (never served). `npm run images` generates AVIF + WebP at 480/768/1080/1600 (never upscaled), blur placeholders (`config/photos.generated.ts`, generated, do not edit) and the 1200x630 OG images. Then list them in the product's `images` array in `config/products.ts` (order: pouch-hero, flat-lay, sachet-open, ingredients; each with `kind`, `src` base path, specific `alt`, short `label`). Products with 0 to 3 photos fall back to labelled placeholders automatically.
- **Adding photos for a product:** big originals go in `./incoming-images` (git-ignored, deleted afterwards), `node scripts/ingest-image.mjs <file> <slug> <slug>-<kind>` makes the `assets-src/<slug>/*.webp` source, `npm run images` makes the sizes (other products' files do not change). Existing databases receive config photos once at boot (`syncConfigImages` in `lib/seed.ts`). GOLD's flat-lay slot currently shows its pouch hero: `TODO(gold-flat-lay)` in `config/products.ts` and `docs/OPERATIONS.md` section 14 (the supplied flat lay has a typo on the pouch and must not be published). The home hero has a flavour switcher (`components/HeroPouches.tsx`) and one ingredients band per flavour.
- Photos are 4:5. Render them with `<Photo>` / `<ProductImage>` (`<picture>` AVIF+WebP, explicit width/height, lazy). Use `fit="cover"` only inside a 4:5 container; any other ratio must use `fit="contain"` or a focal-point crop that keeps all packaging text visible. Never put glass UI over a label: overlay buttons/counters live in the top corners only.
- The only explicit preload is the home hero photo (`components/Hero.tsx`). Do not add `priority`/preload to other images.
- Do not redraw or recolor the logos in `public/brand/` (`miel-m-plus.png`, `miel-full.png`).

## Design system (defined in `app/globals.css`)
- Colors: base `#23201C`, off-white `#F2EFE8`, acid `#DAFC69` (CTAs, key words, numbers only), borders `#3A3631`, muted `#8A857D`, body text `#CFCCC4`. Dark only.
- Type: Archivo (width axis) + Space Mono only, via `next/font`.
  - `.display`: Archivo 125 width, 800, UPPERCASE, line-height 1.05, solid (never transparent).
  - Body: Archivo 100 width, 400, 18px, 1.55, `#CFCCC4`.
  - `.mono`: Space Mono, acid, uppercase, 13px minimum (spec lines, labels, breadcrumbs).
- Buttons: `.btn` is solid acid with black text, 14px radius, inset highlight, min height 56px, full width on mobile; never glass. `.btn-ghost` is the glass-look secondary. `.icon-btn` is a glass circle.
- Glass: `.glass` (cards/panels), `.glass-strong` (header, drawer, sticky bar), `.glass-accent` (hover/selected/featured), `.glass-hover` (accent + 4px lift on hover/focus/tap), `.glass-flat` (same look with NO backdrop-filter, for small chips/tiles).
  - Max about 8 backdrop-filter elements visible at once on mobile; use `.glass-flat` for small repeated items. Blur drops to 10px under 640px. Animate only transform and opacity. `@supports` fallback and `prefers-reduced-motion` are already in the CSS.
- Every section needs something behind the glass: use `<Blobs>` (glow blobs) inside a `relative isolate overflow-x-clip` section. Only the hero blobs float (`<Blobs float>`); keep the rest static for performance.
- Text sizes: mobile hero 40px+, section headings 30px+, product names 26px+ (36px+ on product pages), body 18px. Tap targets at least 48px.
- Header: floating glass pill (`components/Header.tsx`), sticky, 12px from the edges, logo 36px tall mobile / 44px desktop. Keep logos clear of other elements by half their own height on all sides. Hero logo is `min(80vw, 520px)` and slides in from the left over 500ms.
- Motion is subtle: fade-up on scroll (`<Reveal>`), yellow underline on link hover.

## Structure
- `app/(store)/page.tsx`: home (the storefront lives in the `(store)` route group, which adds the cart, announcement bar and tracking; the admin has its own layout) (hero with pouch photo panel, proof strip, lineup (4:5 cards), RED BURN feature band (`components/FeatureBand.tsx`, product set by `FEATURED_SLUG` in `config/site.ts`), how-to, why honey, value, FAQ, final CTA, footer). Lineup cards link to product pages.
- `app/(store)/products/[slug]/page.tsx`: product page template. `generateStaticParams` + `generateMetadata` (title, description, OG) + Product JSON-LD. `opengraph-image.tsx` makes a per-product OG image. Unknown slugs hit `app/not-found.tsx`.
- Product page order: breadcrumb → hero (gallery | name, descriptor, chips, description, price + per-sachet, flavour switcher, qty + ADD TO CART, trust row) → "12 sachets per pouch" flat-lay block (only if the product has a flat-lay photo) → What's inside (spec table + ingredients/allergens/warnings accordion) → How to use (sachet-open photo beside the steps) → Why this one (ingredients photo as a dimmed background) → Compare strip → FAQ → Final CTA. A product `warning` (e.g. GOLD caffeine notice) shows in the info column under the description, not in the FAQ.
- Product page components: `components/product/Gallery.tsx` (4:5 scroll-snap carousel, dots on mobile, thumbs on desktop, counter + zoom button in the top corners, full-screen zoom lightbox rendered in a portal with close button, swipe and arrow keys), `BuyBox.tsx` (qty, add to cart, mobile sticky bar that appears once the main button has scrolled above the viewport, via a scroll check, not IntersectionObserver; hides while the cart is open), `Sections.tsx` (everything else).
- Commerce: `components/CartProvider.tsx` (localStorage cart), `CartDrawer.tsx` (cart + checkout: delivery zone, discount code, cash on delivery), `app/actions/checkout.ts` (server action: validates, rate-limits, prices on the server, creates customer + order, deducts stock, returns the WhatsApp message), `lib/orders.ts` (quote, createOrder, setOrderStatus, stock). TODO: real payment gateway and delivery integration.
- Storefront data comes from `lib/catalog.ts` `getCatalog()` (database when configured, otherwise `config/*` as fallback). With no database, checkout is WhatsApp-only as before.
- Site-wide settings (currency, pouch price, WhatsApp number, Instagram, site URL): `config/site.ts`.
- Favicon, apple icon and OG images are generated from the M+ logo with `npm run icons`.

## Admin panel (`/admin`)
Shopify-style back office for the Lebanon store. Separate layout (`app/admin/layout.tsx`), `noindex` (meta + `X-Robots-Tag` in `proxy.ts` + `Disallow` in robots), protected by `proxy.ts` AND re-checked in every page/action/route with `requirePerm(...)` from `lib/auth.ts`.

**Rule: new admin pages reuse the same building blocks** from `components/admin/ui.tsx`: `Card`, `Money` (split-tone: whole part off-white, decimals muted), `Num`, `Delta`, `StatusBadge`/`PayBadge`, `PageHeader` (title + short gradient band), `DataTable` (table on desktop, stacked cards on phones), `Field`, `KV`, `Empty`, `ErrorState`. Forms use `ActionForm` + `SubmitButton` (`components/admin/ActionForm.tsx`, with a `confirm` prop for destructive actions). Charts use `BarChart`. Section tabs use `SubNav`. CSS classes: `.admin-card`, `.admin-band`, `.pill-btn` (+ `pill-light|lime|glass|danger`), `.status st-*`, `.a-input`, `.a-table`.

- **Stack/data:** SQLite (better-sqlite3, WAL) on the Railway volume (`DATABASE_PATH`, production `/data/miel.db`). Versioned SQL in `/migrations/*.sql`, applied at boot in transactions (`lib/db/core.ts`); a failing migration stops the server. All data access goes through `lib/db` `getDb()`, a parameterized SQL builder with the same call shape as before (`from().select().eq()...`); table/column names are whitelisted in `lib/db/schema.ts` (add a column to the migration AND the registry; a test compares them). Money is stored as INTEGER cents (`*_cents`, discounts `value_x100`); the builder converts to dollars for the app. Every editable record has a `version` (use `.ifVersion(n)` for optimistic concurrency). Placing an order is ONE `BEGIN IMMEDIATE` transaction (`placeOrder` in `lib/orders.ts`), stock changes only inside such transactions. There is no hosted database and no RLS: the file is only reachable from server code, so the role checks ARE the access control. A test fails if any reference to the old hosted service returns.
- **Environments:** `MIEL_ENV` production/staging/development, validated at build (`next.config.ts`), boot (`instrumentation.ts`) and `npm run check-env` (`lib/env.ts`). Production requires `DATABASE_PATH`, `AUTH_SECRET`, `NEXT_PUBLIC_SITE_URL` (https) and mail configuration (`MAIL_FROM` + `BREVO_API_KEY` or SMTP). No demo, preview or bypass mode may be added: the build is tested for their absence.
- **Site mode:** `SITE_MODE=live|maintenance` (`lib/site-mode.ts`, read at REQUEST time). In maintenance `proxy.ts` rewrites every public page to `/maintenance` (branded, HTTP 503, Retry-After, noindex; no form, no email capture, no health claims) and answers JSON 503 to every other public request; `robots.txt` disallows all. The checkout actions, `/api/track` and the web-order transaction refuse by themselves too. Admin, its auth routes, `/api/health`, uploads and static files stay open; the admin shows a banner. Never add a public order/cart entry point without the `inMaintenance()` guard.
- **Add member (owner only):** `addMember` in `settings/team/actions.ts` -> `lib/members.ts` creates an ACTIVE account with a generated temporary password (`lib/temp-password.ts`, shown once via `ActionState.copy`, only the argon2id hash stored, never logged or audited), flags `must_change_password` + `must_enroll_mfa` and a 48 h `temp_password_expires_at` (migration 0003). `lib/auth.ts` makes `requireAdmin` redirect to `/admin/change-password` first, then `/admin/mfa` (forced enrolment); `getAdmin()` is null until both are done; expired temp passwords fail login and invalidate sessions (`lib/session.ts`). `canGrantRole` (`lib/roles.ts`) stops anyone granting a higher role. The Invite flow is unchanged. Accounts are created only in `lib/invites.ts` and `lib/members.ts` (a static test enforces it).
- **Admin preview:** in maintenance a fully signed-in admin (any role, 2FA done) passes `proxy.ts` and sees the real storefront with `components/PreviewBar.tsx` (decided from the session in the proxy AND `lib/preview.ts` in the actions, never from browser input). Real orders stay blocked for admins too: `placeOrder` only accepts an explicit `TEST_ORDER_CONFIRMATION`, which creates an `is_test` order (migration 0002; TEST badge, excluded from `lib/stats.ts`, no WhatsApp, no alert email). `quoteAction` is allowed for the preview admin; `/api/track` and `captureCheckout` stay closed.
- **Email is optional:** `lib/mail.ts` is a safe no-op when `MAIL_FROM` + `BREVO_API_KEY`/`SMTP_URL` are missing (audit-logs `email_not_sent`, one startup warning, admin banner, `/api/health` reports `mail`). Invites/resets then return a one-time `link` shown in the admin (`ActionState.copy`). Never make a feature hard-depend on email.
- **Roles** (`lib/roles.ts`, `PERMS` map): owner (everything incl. settings, team, backups, deleting), manager (operational, exports; no team/settings/delete), staff (orders, customers, inventory, view products; no exports). Check with `requirePerm("orders.write")` at the top of EVERY page, server action and route (`getAdmin()` + 401/403 in route handlers). Add new permissions to `PERMS` AND classify every new action in `tests/integration/auth-gates.test.ts` (the test fails for unclassified actions).
- **Tables:** products, product_images, inventory_items, stock_movements, batches, customers, orders, order_items, order_events (timeline), discounts, shipping_zones, delivery_partners, abandoned_checkouts, events (funnel), pages_content (faq/announcement/hero/testimonials), settings (store/tracking/notifications/policies), admin_users, audit_log. Rows created by the demo generator carry `is_demo = true`.
- **Stock** only changes through `adjustStock` (`lib/db/core.ts`, atomic, writes `stock_movements`, the database also refuses negative stock). Orders deduct on creation (drafts deduct when confirmed); cancel/return restore exactly once (guarded by `orders.stock_deducted`). Prices, shipping and discounts are always computed on the server (`quoteSync`). Checkout sends an idempotency key, so a double click or retry never places two orders. The storefront shows SOLD OUT when stock is 0 (`isSoldOut` in `lib/catalog.ts`).
- **Affiliates (influencers):** `lib/affiliates.ts` (data, commission lifecycle, payouts, applications), `lib/affiliate-math.ts` (pure cents maths), rules and tier rates in `config/affiliates.ts` (migration 0005; `affiliates`, `affiliate_payouts`, `affiliate_applications`, order columns `affiliate_id/code_used/discount_amount/commission_amount/commission_status/commission_payout_id`). A code is looked up in `quoteSync` after discount codes (one namespace, `codeTaken`), the follower discount is % of the PRODUCTS subtotal, the commission is fixed at order creation on the discounted subtotal, `setOrderStatus` voids it on cancel/return, `approveDueCommissions` (14 days after delivery, run on page load and before a payout) approves it, `recordPayout` pays it. Admin: `/admin/affiliates` (`affiliates.read|manage`, owner + manager), public: `/ambassadors` (application form, spam protected) and `/partner/[token]` (private read-only stats, noindex). Docs: `docs/OPERATIONS.md` section 15.
- **Auditing:** call `audit(admin, action, entity, id, details)` (`lib/audit.ts`) for every important change. Never hard-delete business data: archive/disable instead.
- **Pages:** dashboard `/admin`; `orders` (list, `[id]`, `new`, `export`), `/admin/print` (packing slip/invoice); `products` (list, `new`, `[id]` with image manager); `inventory`; `customers`; `marketing` (overview, `discounts`, `content`); `analytics` (+`export`); `settings` (store, `shipping`, `team`, `activity`). Server actions live in an `actions.ts` next to each page.
- **Live alerts:** `lib/events.ts` is an in-process bus (single replica!); `/admin/api/events` streams Server-Sent Events to `components/admin/NotificationBell.tsx` (toast, badge, mutable sound, `router.refresh()` on dashboard/orders/inventory). On disconnect it polls `/admin/api/notifications` every 30 s and refetches on every reconnect. Search: Cmd/Ctrl+K (`CommandPalette`, `/admin/api/search`).
- **Images:** admin uploads go through `lib/storage.ts` (validated, EXIF stripped, AVIF+WebP at 480/768/1080/1600, never upscaled) into `DATA_DIR/uploads` and are served by `app/uploads/[file]/route.ts` (exact filename pattern only, immutable caching). `product_images.src` for uploads is `/uploads/<id>@<widths>@<W>x<H>` (rendered by `components/Photo.tsx`). The built-in photos in `public/images` are untouched.
- **Backups:** `lib/backup.ts`: nightly online-API snapshot into `/data/backups` (newest 14 + 8 weekly), optional encrypted S3 copy (`BACKUP_S3_*`), owner-only zip download (`/admin/backup/download`), `npm run restore -- <file> --yes`, `/api/health` reports the newest backup's age.
- **Demo data:** only through scripts, never the UI: `npm run seed-demo -- --yes` (staging only; refuses production), `npm run purge-demo [-- --confirm]` (CSV backup to `/backups`, deletes only `is_demo` rows, lists ambiguous rows instead of deleting).
- **Auth:** own implementation, no third-party service. Email + password (argon2id, `lib/passwords.ts`), database sessions (`lib/session.ts`: the cookie holds a random token, the DB only its sha256; 12 h idle, 7 d max; `proxy.ts` and `lib/auth.ts` both check), TOTP 2FA with one-time recovery codes (`lib/totp.ts`, secrets AES-GCM encrypted with `AUTH_SECRET`), invitation-only accounts and password resets via single-use hashed tokens (`lib/invites.ts`, links built by `lib/site-url.ts`, mailed by `lib/mail.ts`: Brevo API or SMTP, fails loudly in production), DB-backed rate limits (`lib/rate-limit.ts`, `lib/security.ts`), audit log. No sign-up code or route exists. Pages: `/admin/login`, `/admin/forgot`, `/admin/set-password` (public, token is the credential, used on form submit), `/admin/mfa`, `/admin/account` (sessions list, sign out everywhere, recovery codes). First owner: `npm run create-owner -- --email <email>` (emails an invite, never takes a password, refuses if an owner exists).
- Gotcha: in server actions, `redirect()` throws; don't swallow it in a `try/catch` (re-throw errors whose digest starts with `NEXT_REDIRECT`).

## Hosting (Railway)
- `next.config.ts` uses `output: "standalone"` and keeps native modules external. `npm run build` = `next build` + `scripts/prepare-standalone.mjs` (copies static files, `public` and `migrations`). `npm start` = `scripts/start.mjs` (binds `0.0.0.0:$PORT`). `railway.json`: health check `/api/health` (real query + volume writable, 503 without details), restart policy, **`numReplicas: 1`** (one SQLite file on one volume, in-process alert bus). The Railway **volume is mounted at `/data`**; it is only mounted at runtime, never during the build, and the build never opens the database.
- The storefront is rendered per request (`dynamic = "force-dynamic"`), so admin edits are live immediately and a fresh deploy never shows stale pre-rendered data.
- **Absolute URLs come only from `lib/site-url.ts`** (`siteUrl()`, `absoluteUrl()`, `inviteUrl()`, `resetUrl()`), which reads `NEXT_PUBLIC_SITE_URL`. Never build a URL from request headers or a hardcoded domain. All env vars must exist at build time.
- E2E tests (`tests/e2e/*.spec.ts`) run `npm run build && npm start` (via `tests/support/e2e-start.mjs`) on a throwaway SQLite file. No service is mocked. Operations guide: `docs/OPERATIONS.md`.

## Commands
- `npm run dev`, `npm run build`, `npm run images`, `npm run icons`. Quality gate: `npm run verify` (typecheck, lint, unit, integration on a real temp SQLite, build, E2E on a production build). Individual: `npm test`, `npm run test:e2e`, `npm run check-env`. Scripts: `create-owner`, `backup`, `restore`, `seed-demo`, `purge-demo`.
- Gotcha: sections are `isolate` stacking contexts, so any `fixed` overlay rendered inside a section (sticky bar, lightbox) is trapped under later sections. Render those with `createPortal(..., document.body)`.
- Gotcha: write only the standard `backdrop-filter` in CSS (the build adds the Safari prefix). Writing both made the minifier drop the standard one, which silently disabled blur in Chrome/Edge.
- Gotcha: `.icon-btn` sets `position: relative` in unlayered CSS, so Tailwind `absolute` on it needs `!absolute`.
